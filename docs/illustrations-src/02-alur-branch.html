logis-pr v2 · alur branch

Branch tiket lahir dari production, ke development lewat -dev

Branch tiket kamu tetap bersih dan siap naik ke production kapan aja. Urusan development (termasuk konflik) dikerjain di branch LOGIS-XXXX-dev, yang dibikinin otomatis sama logis-pr.

fitur Bikin fitur baru

Kamu cuma ngoding di LOGIS-1234. Sisanya diurus logis-pr.

  1. 1git switch production && git pull
  2. 2git switch -c LOGIS-1234
  3. 3Ngoding, terus logis-pr -m "…". PR LOGIS-1234-dev → development jadi sendiri.

hotfix/ Benerin bug di production

Ke production langsung dari branch hotfix, ke development tetap lewat -dev.

Pas branch-nya diawali hotfix/, logis-pr bakal nanya:

? Branch hotfix: PR ke mana?
❯ production dan development ← default
  production saja
  development saja

✖ Jangan begini

  • bikin branch tiket dari development atau staging
  • git merge development ke branch tiket
  • cherry-pick / merge commit tiket orang lain

Branch kamu jadi bawa kerjaan orang lain yang belum lolos QA. logis-pr bakal langsung nolak dan nunjukin commit mana yang nyasar.

Konflik sama development? Beresin di -dev

Branch tiket jangan disentuh. Konflik khusus development cukup diselesaikan di branch -dev:

git switch LOGIS-1234-dev
git merge origin/development # beresin konflik → commit
git switch LOGIS-1234 && logis-pr
💡
Kenapa ada -dev? Dulu konflik sama development harus diberesin di branch tiket, dan godaannya pasti merge development. Akibatnya isi development ikut nebeng ke production. Sekarang branch tiket cukup sinkron sama origin/production (itu boleh), sementara urusan development tinggal di -dev.
Sebelum PR dibuat, merge ke tiap target disimulasiin dulu. Konflik? Berhenti.github.com/juanddev/logis-pr
