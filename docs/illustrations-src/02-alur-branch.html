logis-pr · alur branch

Semua branch lahir dari production

Biar yang naik ke production cuma kerjaan yang memang siap, bukan "nebeng" fitur lain yang masih di development.

feature/ Bikin fitur baru

Cabang dari production, PR-nya ke development.

  1. 1git switch production && git pull
  2. 2git switch -c feature/LOGIS-1234-nama-fitur
  3. 3Ngoding, terus logis-pr -m "…". PR otomatis ke development.

hotfix/ Benerin bug di production

Cabang dari production juga, PR-nya bisa ke dua-duanya.

Pas branch-nya diawali hotfix/, logis-pr bakal nanya:

? Branch hotfix: PR ke mana?
❯ production dan development ← default
  production saja
  development saja

Jangan begini: bikin branch dari development

Branch kamu jadi ikut bawa commit orang lain yang mungkin belum lolos QA. Kalau nanti naik ke production, ikut kebawa semua. Makanya logis-pr langsung nolak dan nunjukin commit mana yang nyasar.

Solusinya: bikin ulang branch dari production, terus git cherry-pick commit kamu aja.

Sebelum PR dibuat, merge ke tiap target disimulasiin dulu. Konflik? Berhenti.github.com/juanddev/logis-pr
