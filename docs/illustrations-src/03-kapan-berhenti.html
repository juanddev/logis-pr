logis-pr v2 · kapan berhenti?

Kalau logis-pr berhenti, itu justru lagi nyelametin kamu

Hampir semua pengecekan jalan sebelum commit. Jadi kalau berhenti, belum ada yang ke-push, belum ada PR, dan grup belum dapat pesan apa-apa. logis-pr juga nggak pernah reset, stash, hapus, atau force push apa pun.

Branch bawa commit yang bukan punya tiketexit 1

Ada commit dari development, staging, atau tiket lain, entah lewat branch dari development, merge development, atau cherry-pick. Yang di-cherry-pick (SHA beda) juga ketahuan karena isi patch-nya dicocokin.

✖ BRANCH TIKET MEMBAWA COMMIT YANG BUKAN MILIK TIKET ✖ Commit milik 'development' (belum ada di production): (6) ✖ 7ba1cd0 LOGIS-371: fitur dev 1 ✖ … ✖ Merge commit yang membawa history non-production: (1) ✖ fdd105f Merge 'origin/development' into LOGIS-3972
Benerinnya: bikin branch baru dari production, terus ambil commit kamu aja.
git switch production && git pull
git switch -c LOGIS-3972-v2
git cherry-pick <sha-commit-kamu>

Ada merge yang belum kelarexit 1

Kamu lagi di tengah git merge / cherry-pick / rebase. Kalau logis-pr commit sekarang, merge itu ikut "diberesin" dan seluruh history development bisa nebeng. Jadi logis-pr berhenti, dan merge-nya nggak diselesaikan maupun di-abort.

✖ ADA OPERASI GIT YANG BELUM SELESAI: merge ✖ Commit sekarang akan ikut menyelesaikan operasi itu ✖ dan bisa membawa history branch lain ke branch tiket. ✖ Tidak ada yang diubah.
Benerinnya: batalin sendiri kalau nggak sengaja, git merge --abort (atau git cherry-pick --abort). Cek git status, terus jalanin logis-pr lagi.

Bakal konflik sama target PRexit 2

Sebelum PR, logis-pr nyobain cherry-pick ke -dev dan merge ke target dulu. Semua itu simulasi di worktree sementara, jadi branch dan file kamu nggak disentuh. Ada file bentrok? Stop.

✖ KONFLIK — PROSES DIHENTIKAN ✖ Merge LOGIS-3943-dev → development ✖ akan konflik di 1 file: ✖ src/app.ts
Benerinnya: konflik khusus development diberesin di -dev, bukan di branch tiket:
git switch LOGIS-3943-dev → git merge origin/development → beresin → commit → balik ke branch tiket → logis-pr

Isi PR di GitHub beda dari yang dicekexit 3

Setelah PR dibuat, commit dan file-nya dicocokin lagi sama hasil validasi lokal. Kalau beda (misal ada yang nge-push ke branch yang sama barengan), reviewer, Jira, dan Teams nggak dijalanin.

✖ ISI PR DI GITHUB TIDAK SAMA DENGAN VALIDASI LOKAL ✖ PR #901 (LOGIS-3971-dev → development): ✖ 1 commit di GitHub tidak ada di validasi lokal ✖ Reviewer, Jira, dan Teams TIDAK dijalankan.
Benerinnya: buka tab Commits / Files di PR. Kalau isinya salah, ubah ke draft atau tutup PR-nya, terus cek pakai logis-pr --audit.

Stop yang lain (gampang dibenerin, cek juga pakai logis-pr doctor):

-dev isinya aneh / bercabangBranch nggak ditimpa. Cek git log origin/production..LOGIS-1234-dev, kalau salah rename: git branch -m … …-old.
production nggak ada di remoteNggak diganti diam-diam ke main. Set productionBranch / remote.
Lagi di production / development / -devPindah ke branch tiket dulu.
gh belum login · config kurang · key tiket nggak ketemugh auth login, logis-pr init, atau pakai -t.
